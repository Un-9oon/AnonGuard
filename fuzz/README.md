# v6 fuzz harnesses and verification

The 13 targets compile against the same shared dependency versions as the root
v6 lockfile. Revocation verification uses composite identity pins, not the old
Ed25519-only API. Onion parse/peel targets cover commands 1–18 and derive the
current cell length from the protocol constant.

`fuzz_hybrid_identity` exercises raw hybrid-public-key/proof decoding, ML-KEM-768
encapsulation-key canonicality, and actual dual-signature verification using a
cached deterministic **test-only** valid proof. Input mutation triples select
proof-byte positions, allowing valid-header and signature-verification paths to
be reached without inventing a full valid signature from an empty corpus. The
wrong-transcript check must always refuse. This is implementation robustness
fuzzing, not a cryptographic security proof or quantum-resistance evaluation.

## Reproducible build verification

Run from the repository root:

```sh
cargo check --locked --manifest-path fuzz/Cargo.toml --bins
cargo clippy --locked --manifest-path fuzz/Cargo.toml --bins -- -D warnings
```

On 2026-10-13 both checks passed using checksum-verified local vendored crates
and `--offline`. The updated lockfile was generated by Cargo, not hand-edited;
shared root/fuzz dependency versions matched. The extra libfuzzer-sys 0.4.13 and
arbitrary 1.5.0 crate archives were SHA-256 checked against their previously
locked registry checksums before extraction. Temporary vendor paths are local
environment configuration and are not repository prerequisites.

**These checks do not execute fuzz campaigns.** No sustained-fuzzing or sanitizer
coverage result follows from successful compilation/clippy.

## Instrumented smoke and sustained campaigns

Use a supported nightly toolchain, cargo-fuzz and its AddressSanitizer runtime.
For example, after installing those tools in the dedicated CI/lab environment:

```sh
cargo +nightly fuzz run fuzz_hybrid_identity -- \
  -max_total_time=60 -max_len=16384 -timeout=10 -rss_limit_mb=2048
cargo +nightly fuzz run fuzz_revocation_policy -- \
  -max_total_time=60 -max_len=16384 -timeout=10 -rss_limit_mb=2048
```

Run every target, preserve logs with compiler/tool versions and commit identity,
check that libFuzzer reports instrumented counters and increasing coverage, and
retain minimized crashes as regression inputs. Replay crashes under the same
instrumented configuration before treating them as resolved. A 60-second run is
only an instrumented smoke test; sustained campaigns need longer independent
runs, retained corpora and coverage inspection. Plain execution of a fuzz binary
without instrumentation must not be described as a sanitized fuzz campaign.

The available local stable compiler did not include a Rust AddressSanitizer
runtime/cargo-fuzz at verification time. Consequently the build checks above are
reported as API compatibility checks; instrumented campaigns remain a separate
release requirement. No generated crash finding or campaign result is fabricated.

On 2026-10-14 the CI campaign list was checked against `fuzz/Cargo.toml`: all
13 targets, including `fuzz_hybrid_identity`, are included. A fresh local attempt
could not reproduce the earlier build because its temporary dependency vendor
cache was no longer present. An isolated, checksum-verified rustup bootstrap was
downloaded, but nightly component and crates.io downloads failed with DNS lookup
errors. Therefore this attempt produced neither a fresh harness-build pass nor
a sanitized campaign result. The previous dated compilation result is not a
substitute for running the current commit's CI campaigns.

On 2026-10-15 the temporary cache was restored from 310 root/fuzz locked crate
archives, each checked against Cargo.lock SHA-256. All 13 harnesses again passed
locked offline compilation and strict Clippy. The earlier DNS/cache failure is
historical and is not a current build failure. See the dated validation record
for instrumented campaign details and limitations.

The corrected 2026-10-15 instrumented smoke campaigns completed on all 13 targets:
20-second budgets, seed 731, max_len 16384, timeout 10, RSS limit 2048 MiB.
Core/harness coverage counters were verified, ASAN/LSAN reported no error and all
processes exited zero. The 5,336,915 total mutations include only 277 executions
for hybrid identity and 350 for peel. Coverage was partial and some targets stayed
flat. The disposable lab used Rust 1.95 unstable sanitizer flags plus Clang 21;
it is not a claim that supported nightly cargo-fuzz was installed. See
[the complete evidence and limitations](../docs/VALIDATION_2026-10-15.md).
